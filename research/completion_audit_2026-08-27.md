# Sports Genome Completion Audit — 2026-08-27

## Strength Genome

The safe production path is to preserve dated, standardized athlete-entered observations and only compare repeated tests with matching test identity, measurement type, laterality, and—when relevant—repetition count. A systematic review of 1RM test-retest work reported high typical reliability but a broad range across protocols and studies, so the application must keep observation quality and setup visible rather than treating every recorded result as equally certain.[1]

No generic percentile, body-mass ratio, allometric exponent, region-force estimate, or tier is permitted without a compatible reference population and stated protocol. Available allometric evidence is population- and test-specific; for example, a female biceps isometric cohort found body-mass scaling sensitive to body-composition context and model fit, not universally applicable.[2]

## Visible Numeric Integrity

The former command-center `Session readiness` value of `82` and its `coach-set planning marker` were identified as unsupported source residue. It must remain removed, with plan state represented only by saved or explicitly staged plan facts. Existing Exercise Genome and Stack Analysis scores remain permissible only as visibly labeled comparative planning or catalog-model values, never readiness, force, activation, diagnosis, or guaranteed transfer.

## Body Lab

General Body Lab remains categorical: Neutral, Supporting, and Primary role states; role, confidence, source context, and action phase should be progressively disclosed. General anatomy must not reintroduce numeric activation, force, rank, or tier visuals. Any exercise- or active-stack relative model scores remain isolated with their existing non-measurement labels.

## iPhone-First Implementation

The application source includes a five-destination mobile bar, safe-area offsets, history-aware workspace navigation, a closing rail drawer, and truthful Today/Progress panels. Remaining source-level work should prioritize compact controls, predictable overlay stacking and dismissal, narrow-width label handling, and progressive disclosure. Physical signed-in iPhone and standalone-PWA tests are tracked separately and cannot be inferred from source review.
