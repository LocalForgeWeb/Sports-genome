## 1. Runtime shape

- `api/[...path].js` re-exports `dist/serverless.js`, which is built from `server/_core/serverless.ts`. That entry is a bare Express app with `trust proxy 1` (`serverless.ts:25`) and a 4 MB JSON/urlencoded parser (`:28-29`). It mounts `createExpressMiddleware({ router: appRouter, createContext })` (`:53-59`) with **no `onError`, no `maxBatchSize`, no errorFormatter, no rate limiting, and no CORS or security headers**. CONFIRMED.
- `vercel.json` rewrites `/api/trpc/:path*` to the function, and the path comes back through `__trpc` (`serverless.ts:40-51`).
- `server/_core/index.ts` is the dev server (50 MB body limit, not deployed). `server/index.ts` is a static-only server.
- tRPC batching is on by default and uncapped. **[probe]** Three public procedures in one GET (`strengthPercentile.forLifts,strengthProfile.muscleRanks,strengthPercentile.forLifts?batch=1`) returned 200 with three results. CONFIRMED.
- The superjson transformer lets clients send `NaN` and `Infinity`. **[probe]** zod 4 rejects both with 400. CONFIRMED.

## 8. Account deletion and export (B188)

- **Neither exists.** There is no procedure, UI, RPC, or script for deleting or exporting an account (grep for delete/export/erase patterns across `client/src`, `server`, `shared`, `supabase`). CONFIRMED.
- MySQL: every user-owned table cascades from `users.id`, so deleting a single `users` row would remove sessions, sets, observations, plans, favourites, passkeys and credentials. No code deletes `users`.
- Supabase: focus, constraint and check-in rows cascade from `auth.users` (in the repo). Cascade on `athlete_profiles` and `athlete_strength_entries` is unknown. Rows belong to an anonymous identity whose only credential is in `localStorage`, so clearing site data orphans them with no path to delete them. They include health-adjacent context such as `constraint_type` `symptomatic` or `clinician_restricted`.
- Local: `rebuildPlan` clears only the scoped profile and plan keys (`Home.tsx:1380`). Device history, observations, weight log, sync queue and the Supabase session remain.
