# Exercise photographs

**Source.** The Free Exercise DB (github.com/yuhonas/free-exercise-db), released into the public domain under the Unlicense. Hugging Face mirrors its records as the dataset `sirnino/bodybuilding-exercises` (Apache-2.0 metadata; the JSON only, without the images), which is where the photos were traced from. The `SportGenome` Hugging Face account itself holds no repositories, so the mirror's upstream is used directly. Each source exercise has two photographs, the start and the finish of the movement, one model, one background. No new photographs were generated for the October 1 update; integration was improved, and a review of every photograph shared by more than one catalog exercise withdrew 17 plausible-but-incorrect variations (a single-arm press shown with the two-arm photo, a weighted push-up shown without the plate, a bench hip thrust shown as a floor bridge, and so on; the list and each reason are the `rejected` table in `scripts/exercise-photos/curate.mjs`). Those exercises now show the placeholder frame. The variant sets checked by name are recorded in `docs/ux-oct1/evidence/acceptance.json` (P2, P5).

**One component.** `client/src/components/ExerciseMedia.tsx` is the only exercise-media component, in two variants: `thumb` (one frame beside a name: catalog rows, plan rows, workout prestart rows, the live workout's full-session list) and `detail` (start and finish, captioned, with the credit and the boundary "the photographs identify the exercise; they are not a full technique demonstration": Exercise Intelligence and, collapsed behind one line, the live set card). Media is chosen by the exercise's stable catalog id through the curated map, never by position in a list or by a name resemblance at render time. An exercise with no photograph gets the same frame holding its equipment's icon from the app's icon family, so rows line up and no row borrows another exercise's photo.

**Media record.** `client/src/data/exercisePhotos.json` maps `exerciseId → [sourceFolder, frameCount, width, height]`. The sizes are read from the files at the pinned commit by `scripts/exercise-photos/dimensions.mjs` and are what the component uses to reserve each frame's box before the bytes arrive (`width`/`height` attributes, and the frame box sized from its own width, with the image laid over it). Alternative text is "{exercise}, start position" / "{exercise}, finish position" on the detail frames; a thumbnail beside the exercise's own name is `alt=""` and hidden from the accessibility tree so the name is not read twice. A per-photo focal position (`focalBySource` in `exercisePhotos.ts`, CSS object-position) is carried with the record for frames that need one; none do yet, because every frame is shown at its own shape.

**Frames and treatment.** The photographs are landscape 3:2 (197 of 229 are 850×567; 16 are portrait, 1 square, 2 are 16:9). Thumbnails are therefore a 3:2 frame, 88×59 CSS px in the catalog and 72×48 in dense plan and workout rows (the brief's 76–88 px square was judged against the 3:2 source: a square would centre-crop a third of every photograph, so the frame follows the photograph instead), inset with the content, 10 px radius, a hairline edge, a dark ground, and the photograph left natural. A portrait or square frame is shown whole inside the thumbnail (`object-fit: contain`) rather than cut to a strip. The detail frames take each photograph's own aspect ratio.

**Loading and failure.** Images are `loading="lazy"`, `decoding="async"`, no referrer. The CDN is asked first; a frame that fails is asked for once from the second host; a frame that fails there too becomes the placeholder frame (no broken-image icon, no retry loop, no row that disappears). Thumbnails and detail frames fetch the same source files: the source publishes one size per photograph, so a thumbnail is the same bytes drawn smaller. There is no shimmer; the frame's dark ground is the loading state, so reduced-motion needs nothing.

**Serving.** Nothing is copied into this repository. Photos are loaded from the jsDelivr GitHub CDN at a pinned commit (`client/src/lib/exercisePhotos.ts`), with raw.githubusercontent.com as the second host.

**Matching.** `scripts/exercise-photos/match.mjs` normalises names and reports exact matches and fuzzy candidates against the source list; `scripts/exercise-photos/curate.mjs` applies only exact matches and a hand-checked alias table (a fuzzy candidate that is not listed there is dropped: a wrong photo teaches a wrong movement) and writes the map; `dimensions.mjs` adds the sizes. Coverage: 229 of 400 exercises (57 exact name matches, 172 hand-checked aliases; 17 aliases rejected as the wrong variation). Unphotographed groups are mostly landmine, cable-variant and medicine-ball movements the source does not include; those show the placeholder frame.

**To regenerate.** Download `dist/exercises.json` from the source repository, export the catalog (`npx tsx` over `client/src/lib/exerciseCatalog.ts`) into `app-exercises.json`, run `match.mjs` to review new candidates, extend the alias table in `curate.mjs`, run it, run `dimensions.mjs`, and bump `exercisePhotoSourceRef` to the commit the photos were checked against.

**Evidence.** `docs/ux-oct1/evidence/` holds the October 1 captures (catalog at 390 and 320, failed-media state, detail, plan rows, workout prestart, live workout with the collapsed media open) and `acceptance.json`, produced by `docs/ux-oct1/probes/oct1.mjs`. The sandbox browser has no outbound network, so the probe fetches the pinned frames with curl and serves them to the page under their real URLs; the `fail` and `slow` runs abort or delay those same requests. Tests: `client/src/lib/exercisePhotos.test.ts` and `client/src/components/ExerciseMedia.test.ts`.

**Frame order.** The source numbers each pair 0 and 1, and that numbering is not the movement's order: in 30 of the 207 pairs used, frame 0 is the finish (Cable Lateral Raise with the arm already up, dips at the bottom, Smith bench press with the bar on the chest). All 207 were checked by eye; the reversed ones are listed with reasons in `client/src/data/exercisePhotoOrder.json` and shown start-first everywhere. Method, the rule used where the source's wording disagrees with the lift, and the verdict for every pair: `docs/exercise-photo-order/`.
